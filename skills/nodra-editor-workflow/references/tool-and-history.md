# Tools and history

Current tools are select, rectangle, ellipse, line, and pan. Pointer interactions include move, resize, draw, marquee, and viewport pan. `editor-core` owns commands, selection, gesture preview/commit/cancel, and undo/redo. `previewGestureFromBase` prevents pointer-derived corrections from accumulating. A completed gesture creates one transaction; undo and redo move transactions between stacks. Topology-changing commands may expose ephemeral reference maps and diagnostics in their immediate successful result, but that metadata is neither persisted nor copied into transactions; history restores the complete before/after snapshots. Failed commands leave state unchanged. A successful command that returns the same document is a no-op: `dispatch` must leave revision, persistence work, and undo/redo stacks unchanged.

The web composition translates screen points to mm, chooses hits through geometry, and invokes commands. It owns transient pointer capture, drafts, viewport state, and Zustand UI/session stores. A tool must not mutate a snapshot directly or access IndexedDB. Preview state is not a save contract: only the committed project/document is scheduled through persistence. Treat preview as provisional and persistent commit as the only save/history boundary. Test zero-length lines, missing IDs, empty selection, canceled gestures, repeated preview events, no-op commands, multi-selection, and keyboard undo/redo.
